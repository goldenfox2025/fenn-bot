# Fenn Bot visual system

The main surface follows a compact messenger composition: an 80px persistent Bot rail (expandable to named square tiles), a centered identity pill, rounded bubbles capped at 560px, restrained 14px prose and a 44px input pill. `theme.css` owns the neutral palette; `BotAvatar.tsx` renders the original rounded blue-black identities. Main Fenn keeps its fox. Missing avatars receive distinct persisted defaults; changes apply everywhere that identity appears.

Navigation follows the user's Grok references. In the compact rail, Bots lead at the top; create, group and profile/settings actions stay at the bottom. In expanded navigation, search/add occupy the top-right, named 96px Bot tiles wrap in the available width, and profile/connections stay at the bottom. Do not restore a vertical search/add/toggle stack above the first Bot. Dragging the edge changes width; double-click or Ctrl/Cmd+B toggles compact/expanded, and Ctrl/Cmd+K opens search. Preserve the preferred width. Operation records use request summaries and flat expandable items, without a vertical timeline or repeated item times.

Named navigation starts as soon as the 96px tile and 32px total insets fit (128px), with icon-sized footer controls at intermediate widths. Collapsed operation requests occupy 38px rows; expanded content carries its own spacing. Conversation nodes sit 8px inside the edge, with a 24px maximum ridge width and 4px clearance before bubbles. The shared 36px reading gutter stays consistent when nodes appear and across window widths.

The composer grows for multiline messages. Its “＋” menu opens model/backend settings, records and permissions before the first message. Progress appears at the next assistant-message position; approvals occupy that bounded region when needed. No tool counts, tool traces, reasoning or intermediate decisions appear in chat. Clicking the identity pill opens the current Bot's side panel: Details (schedules and activity), Memory, Computer and Permissions. A wide window places a content-sized card beside chat. If two readable columns do not fit, deliberately opening details replaces the chat area with a page and a Back action. It never covers bubbles or the composer. Keep chat mounted so Back preserves reading position and drafts. The rail remains usable. Automatic hiding on resize preserves intent and restores the inspector on widening; explicit closing remains closed.

ACP plain text and reasoning are recorded in a persistent activity journal. A complete user-facing message is delivered only by `send_user_message`. This is a routing contract rather than a CSS-only filter; stopping a task revokes that delivery endpoint too. Repeated delivery requests can use an idempotency key.

Narrow details pages support Escape and restore the opener without trapping navigation in a modal. Nested selectors consume Escape first. Settings and Bot editors use native modal dialogs. All selections use one themed, viewport-aware top-layer listbox, including inside a dialog. Compact labels stay on one line; long names truncate and whole options may move together. Acceptance covers light/dark, narrow/wide, 125%/150% zoom, clipping, focus, switching Bots before resizing, and returning from nested controls. Native WebContents captures are used because Electron CDP screenshots crop incorrectly after page zoom. The original shared fennec identity distinguishes outlined user and solid assistant; subtle live feedback honors reduced motion.


Group chats share the same rail and conversation anatomy. Reply bubbles include the sender’s existing avatar/name. An unaddressed request goes to the host; @ mentions select members. The inspector shows each member’s group-scoped activity, memory and permissions. Private conversations are independent. There is no global combined operation journal.
